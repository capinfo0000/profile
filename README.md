# ポートフォリオサイト（取扱説明つき）

engineer.v2008.coreserver.jp

作ったプロダクトをコアサーバーのサブドメインで複数運用している。それらを紹介する
ホームページをメインドメインに作る。各プロダクトは利用にログインが必要なため、
**スクリーンショットと説明文による「取扱説明」** の形で見せる。

- 状態: 要件ヒアリング中（第5版・未決23項目）／サイトは構築着手済み
- 最終更新: 2026-08-08

---

## 中身の案内

### `site/` — サイト本体

サーバーに上げるファイル一式。**`site/` の中身**を公開ディレクトリ直下に置く
（`site/` ごと置くとURLが `/site/` 配下になる）。手元で見るときは `site/index.html`
をダブルクリックすれば動く。ビルド不要・外部通信なし。

| ファイル | 役割 |
|---|---|
| `index.html` | トップ |
| `works.html` | 作品ビューア（1件ずつ全画面で送る） |
| `about.html` | 自己紹介 |
| `data/works.js` | **作品一覧のデータ。追加はここだけ触る** |
| `assets/js/pattern.js` | 背景の幾何学模様（四分木で描画） |
| `assets/js/viewer.js` | 作品の切り替えと渦の演出 |
| `assets/js/artwork.js` | 仮の作品画像を生成（本番では写真に差し替え） |
| `assets/js/app.js` | 全体の組み立て・設定パネル |
| `assets/css/style.css` | 配色・書体・寸法のトークン |
| `README.md` | サイト側の詳しい説明 |

### `docs/` — 要件と設計

| ファイル | 内容 |
|---|---|
| `requirements-draft.md` | **要件定義ドラフト（第5版）**。確定事項・ページ構成・非機能要件・サブドメイン棚卸し・段階公開プラン・未決事項 |
| `要件定義書（初版）_ポートフォリオサイト_20260807.docx` | 要件定義書 初版（Word） |
| `design-reference.md` | **参考サイトのデザイン分析**。unshift.jp / daijima.jp の分解、静的HTMLでの再現手順、採否、デザイントークン |
| `hearing-mock.html` | ヒアリング用の仮モック |
| `unshift-style-mock.html` | 構造モック（画面構成の検証用・1ファイル完結） |

### `logs/` — チャットログ

やりとりの全文。判断の経緯を追うとき用。

## いま決まっていないこと

要件定義ドラフト7章に23項目。全体を止めているのは次の2つ。

1. **サービス6本のログイン要否の切り分け** — 第1段階の公開対象が確定しない
2. **作品ごとに色を変える仕組みの採否** — 後から足すのが一番高くつく（一覧データの形が変わる）

デザイン系の論点（カーソル追従・数字めくり・設定パネル・背景の動き・明暗の初期値）は
`site/` が動くので、想像ではなく**見て決められる**状態になっている。

## 進め方

段階公開。要件定義6章のとおり3段階に分ける。

| 段階 | やること | 撮影 |
|---|---|---|
| 第1 | サイトの器（トップ・About・Contact・ポリシー）＋誰でも見られる3本 | 3枚 |
| 第2 | ログインが必要なサービスを取説つきで1本ずつ追加 | 1本 4〜6枚 |
| 第3 | Blog・更新情報、検索対策 | — |

公開後も繰り返し一覧に手を入れるため、`data/works.js` でのデータ管理は必須要件。
