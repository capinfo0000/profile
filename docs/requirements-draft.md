ポートフォリオサイト（取扱説明つき） / engineer.v2008.coreserver.jp

## 1. 背景・目的

作ったプロダクトを複数、コアサーバーのサブドメインで運用している。
それらを紹介する自分のホームページを、メインドメインに作りたい。

各プロダクトは **利用にログインが必要**。来訪者にIDとパスワードを渡すことはできないため、
サイト上では **スクリーンショットと説明文による「取扱説明」** の形で見せる。

サイトの主役はポートフォリオ（作ったもの）。自己紹介も載せるが従。

### Works は2カテゴリに分ける

「動くサービスを作った」ものと「サイトを作った」ものは見る人にとって意味が違うため、
同じ棚に混ぜない。

| カテゴリ | 中身 | 見せ方 |
|---|---|---|
| サービス開発（6本） | RAGチャットボット／駐車場マップ／イベント事前決済／WEB意見箱／ビジネスマッチング／飲みゲーム | ログインが必要なものは画面写真＋説明文で取説形式。誰でも使えるものは実物へのリンクを前面に出す |
| Web制作（2本） | crafy（キャンペーンサイト）／revenge.co.jp（企業HP・運用も継続） | 実物が見られるためリンクのみ。取説は不要。スクリーンショット1枚と役割の記載のみ |

Web制作の2本は撮影1枚ずつで完成するため、第1段階の公開にそのまま使える。
また「サービスも作れるし、サイト制作も受けられる」という幅がカテゴリ分割で一目で伝わる。

### 段階公開プラン

「必要な箇所ができたら公開し、ポートフォリオは随時追加」という方針にあわせて3段階に分割。

| 段階 | やること | 撮影 | この時点の状態 |
|---|---|---|---|
| 第1段階（公開） | サイトの器（トップ・About・Contact・ポリシー）＋**誰でも見られる3本**（飲みゲーム／crafy／revenge.co.jp） | 3枚 | この時点で公開できる。空っぽに見えない |
| 第2段階（随時） | ログインが必要なサービスを取説つきで1本ずつ追加 | 1本 4〜6枚 | 1本仕上がるたびに公開。まとめて作らない |
| 第3段階（任意） | Blog・更新情報、検索対策の追い込み | — | 必要になったら |

要点は「誰でも見られる3本を先に出す」こと。この3本は実物へのリンクで伝わるため取説が不要で、
**撮影3枚で公開までたどり着ける**。ログインが必要な5本は写真を撮りためながら後から足す。

**この進め方の帰結**: 公開後も繰り返し一覧に手を入れるため、一覧のデータファイル管理は
選択ではなく必須要件。1件追加するときはデータファイルに数行足すだけで済む作りにする。

**提案**: まず3本で公開し、残りは後から足す。サイトの作りは変わらないため作り直しにはならない。
また7本規模なら、一覧は **データファイル1つで管理** する方式を推奨（HTML直書きだと更新が止まる）。

### unshift.jp の分析（キャプチャとページソースより）

**制作会社ではなく、東京の個人開発者のポートフォリオ**。トップの一文は
「私は東京を拠点とするクリエイティブ／フロントエンド開発者です」。今回と同じカテゴリ。

| 要素 | 作り |
|---|---|
| 作品の見せ方 | 全画面で1件ずつ表示（58/60）。矢印キー・スクロール・スワイプで送る |
| 画面の使い方 | 中央に作品画像1枚。操作UIはすべて四隅に固定（左上ロゴ／右上ナビ・設定／下中央ページ送り／右下メニュー） |
| 背景 | **作品ごとに色と形を変える幾何学パターンが常時アニメーション**。ハミダシ＝ピンク＋青紫のダイヤ／野菜＝ベージュ＋ピンクの同心円／Property Agent＝グレーの三角。作品の配色から背景を生成している |
| 連動 | 貼り紙ラベルとカーソルの色も作品に連動（Property Agent では両方とも赤） |
| 技術 | 詳細ページのタグ欄に本人が明記：**GLSL / three.js / WebGL / クリエイティブコーディング**。動きの正体はシェーダー |
| ナビ | 「トップ／作品／について」の3つだけ。大きめの文字に広い字間 |
| 画像の縁 | 直角の長方形ではなく、紙を手でちぎったような破れた輪郭 |
| タイトル | 左下に貼り紙風の黒いラベル。文字が少しズレて二重に刷られた効果つき |
| カーソル | 四角形と「詳細はこちら」が追従。作品の明暗に応じて黒⇄白に反転 |
| 設定パネル | 来訪者が選べる：表示モード（満杯/単純/最小）、メニュー位置、ライト/ダーク |
| 切り替え演出 | 画像が砕けて次に変わる。Nuxt.js＋canvas（WebGL）による生成描画 |

### ★ 最重要：ページ全体の配色が作品の色から生成されている

動画のコマ送りで確定。プロダクト1つにつき色を1つ決め、ページ全体に流している。

| 要素 | 水曜日のカンパネラ | Property Agent |
|---|---|---|
| 背景パターン | 紫 | グレー |
| タイトルラベル | 紫の塗り | 赤の塗り |
| タグの丸ボタン | 紫の塗り | — |
| 「閉鎖されています」枠 | 紫がかった灰 | — |
| カーソル | — | 赤 |

**静的HTMLで完全に同じことができる。** 一覧データに `色: "#7B5EA7"` を1行持たせ、
CSS変数に渡すだけ。JavaScriptもシェーダーも不要。

unshift.jp が凝って見える理由の大半がこの仕組み。**今回いちばん費用対効果が高い採用候補。**

### 切り替え演出の分解

| 順 | 起きていること |
|---|---|
| 1 | 画像が上下2枚に割れて飛び去る |
| 2 | それぞれが横方向の短冊に千切れる |
| 3 | RGBがズレる（マゼンタ・シアン・緑の縁） |
| 4 | 次の作品名が中央にフェードイン。背景パターンの色も次の作品の色へ変わる |

グリッチ系のシェーダー。静的HTMLでは再現不可。

### 静的HTMLでどこまで寄せられるか

| やりたいこと | 手段 | 差 |
|---|---|---|
| 背景に幾何学パターン | SVGパターンを敷く | ほぼない |
| パターンがゆっくり動く | CSSアニメーションで平行移動・回転 | 単調な繰り返しになる |
| プロダクトごとに色が変わる | データに色を1つ持たせCSS変数へ | **差はない** |
| ラベル・カーソルも連動 | 同じCSS変数を参照 | 差はない |
| 画像が砕けて切り替わる | — | **再現不可** |

### そのままの構成は今回に合わない

unshift.jp の作品は「水曜日のカンパネラ 公式サイト」のような、画像1枚で成立する制作物。
全画面1件ずつのビューアは、作品が視覚的に強いからこそ機能する。

今回のサービス開発6本はログインが必要な業務アプリで、画面の中身は入力欄と一覧表。
全画面に引き伸ばしても絵として持たず、クリックしてもログイン画面に着く。
**構成は借りず、見た目の作法だけを借りる。**

### 採否

| 要素 | 判断 | 理由 |
|---|---|---|
| 配色（ほぼ白＋作品だけが色を持つ） | 採る | 画面写真が主役の今回と相性が良い |
| 四隅にUIを固定するレイアウト | 採る | 中央を写真に明け渡せる。CSSのみ |
| ナビは3つだけ・広い字間 | 採る | 今回も Works / About / Contact の3つ |
| ライト／ダークモード | 採る | 確定済みのスマホ対応と同じ仕組みで入る |
| うっすらした幾何パターン背景 | 採る | 白一色より締まる。画像1枚 |
| **画像の破れた縁** | ❓ 要確認 | **静的HTMLで実現可**。マスク画像1枚で全写真に適用。JS不要 |
| **貼り紙風タイトルラベル** | ❓ 要確認 | **CSSのみで実現可**。二重のズレ効果も含む |
| カーソルの明暗反転 | ❓ 要確認 | 一覧データに「明るい/暗い」を1項目持たせるだけ |
| スクロール連動の表示 | ❓ 要確認 | 実現可。入れるほどスマホで重くなる |
| 数字がめくれるページ送り | ❓ 要確認 | 一覧形式なら出番がないかもしれない |
| 来訪者が選べる設定パネル | ❓ 要確認 | 表示モード3種＝実質サイト3つ。ライト/ダークのみに絞ることを推奨 |
| 全画面1件ずつのビューア | 採らない | ログイン必須の業務画面に不向き |
| 画像が砕ける切り替え演出 | 採らない | WebGL。静的HTML方針と画像軽量化方針の両方に反する |

**要点**: 構成ではなく「静けさ」を借りる。余白が広く、色を作品にしか使わず、
操作UIを画面の端に追いやる。この3つは今回そのまま効く。業務画面のスクリーンショットは
地味なので、周りが静かなほど写真が引き立つ。

**WebGLが必要なのは「切り替わる瞬間」だけ**だった。止まった状態の破れた縁と貼り紙ラベルは
マスク画像1枚とCSSで作れる。署名になっている見た目は静的HTMLのまま採用できる。

### 判断が必要な論点：方向性

破れた縁と貼り紙ラベルは、手作りっぽさ・勢いのある見た目。unshift.jp は色鮮やかな
広告・音楽系の制作物が並ぶのでこの荒さが似合う。

今回のサイトは採用担当や取引先に「業務システムを任せられる人」として見られる場でもある。
破れた縁は目を引くが、堅さや信頼感とは逆方向に働く。好みではなく、
**誰に何と思われたいか**の問題。

選択肢: A. 採用する（印象重視）／ B. 直角のまま静かに（信頼感重視）／
C. 受託制作の2本だけ採用

### 詳細ページの構成が今回の悩みを解決する

unshift.jp の作品詳細ページは左に情報・右に大きな画像の2カラム。左カラムがそのまま使える。

| unshift.jp の左カラム | 今回への置き換え |
|---|---|
| ← 戻る | 一覧に戻る（同じ） |
| タイトル（塗りラベル）＋日本語サブタイトル | プロダクト名＋1行説明（同じ） |
| カテゴリ：Webサイト | 区分：サービス開発 / Web制作 |
