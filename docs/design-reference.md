## 2. unshift.jp

**制作会社ではなく、東京の個人開発者のポートフォリオ。** トップの一文は
"I'm a Creative / Front-end Developer based in Tokyo."。今回と同じカテゴリのサイト。

### 2.1 全体構成

| 要素 | 作り |
|---|---|
| 作品の見せ方 | 全画面で1件ずつ表示（58/60 のような通し番号）。矢印キー・スクロール・スワイプで送る |
| 画面の使い方 | 中央に作品画像1枚。操作UIはすべて四隅に固定 |
| 四隅の内訳 | 左上ロゴ／右上ナビ・設定／下中央ページ送り／右下メニュー |
| ナビ | 「トップ／作品／について」の3つだけ。大きめの文字に広い字間 |
| 背景 | 作品ごとに色と形を変える幾何学パターンが常時アニメーション |
| 技術 | 詳細ページのタグ欄に本人が明記：GLSL / three.js / WebGL / クリエイティブコーディング |
| 実装 | Nuxt.js（Vue）のSPA。ビジュアルは canvas + WebGL |

背景パターンの実例:

| 作品 | 背景 |
|---|---|
| ハミダシ | ピンク＋青紫のダイヤ |
| 野菜 | ベージュ＋ピンクの同心円 |
| Property Agent | グレーの三角 |

### 2.2 ★ 最重要：ページ全体の配色が作品の色から生成されている

動画のコマ送りで確定。**プロダクト1つにつき色を1つ決め、その色をページ全体に流している。**

| 要素 | 水曜日のカンパネラ | Property Agent |
|---|---|---|
| 背景パターン | 紫 | グレー |
| タイトルラベル | 紫の塗り | 赤の塗り |
| タグの丸ボタン | 紫の塗り | — |
| 「閉鎖されています」枠 | 紫がかった灰 | — |
| カーソル | — | 赤 |

**この仕組みは静的HTMLで完全に同じことができる。** 一覧データに色を1つ持たせ、CSS変数に渡すだけ。
JavaScript もシェーダーも不要。

```html
<!-- 一覧データ側で色を1つ持つ -->
<article class="workCard" style="--work-color:#7B5EA7">
```
```css
.workCard .label   { background: var(--work-color); }
.workCard .tag     { background: var(--work-color); }
.workCard .patternBg { color: var(--work-color); }
```

unshift.jp が凝って見える理由の大半がこれ。**今回いちばん費用対効果が高い採用候補。**

### 2.3 四隅固定レイアウト

中央を作品画像に明け渡し、操作UIを画面の端に追いやる作法。CSSのみで作れる。

```
┌──────────────────────────────┐
│ ロゴ                    ナビ・設定 │
│                              │
│          [ 作品画像 ]          │
│                              │
│ 操作ヒント     ページ送り   メニュー │
└──────────────────────────────┘
```

業務画面のスクリーンショットは地味なので、**周りが静かなほど写真が引き立つ**。
今回の狙いとまっすぐ噛み合う。

### 2.4 細部の作法

| 要素 | 作り | 静的HTMLでの手段 |
|---|---|---|
| 画像の縁 | 直角の長方形ではなく、紙を手でちぎったような破れた輪郭 | マスク画像1枚（`mask-image`）。JS不要 |
| タイトル | 左下に貼り紙風の黒いラベル。文字が少しズレて二重に刷られた効果 | `text-shadow` の二重掛けのみ |
| カーソル | 四角形と「詳細はこちら」が追従。作品の明暗に応じて黒⇄白に反転 | 一覧データに「明るい/暗い」を1項目持たせる |
| ページ送り | 数字がめくれる（オドメーター式） | 0〜9を縦に並べて `translateY`。実装済み（4節） |
| 設定パネル | 来訪者が選べる：表示モード（満杯/単純/最小）、メニュー位置、ライト/ダーク | すべてCSSクラスの付け外し。実装済み（4節） |

### 2.5 切り替え演出の分解

| 順 | 起きていること |
|---|---|
| 1 | 画像が上下2枚に割れて飛び去る |
| 2 | それぞれが横方向の短冊に千切れる |
| 3 | RGBがズレる（マゼンタ・シアン・緑の縁） |
| 4 | 次の作品名が中央にフェードイン。背景パターンの色も次の作品の色へ変わる |

グリッチ系のシェーダー。**静的HTMLでは再現不可。**

ただし**WebGLが必要なのは「切り替わる瞬間」だけ**だった。止まった状態の破れた縁・貼り紙ラベル・
色の連動はすべてCSSで作れる。**署名になっている見た目は静的HTMLのまま採用できる。**

### 2.6 作品詳細ページ

左に情報・右に大きな画像の2カラム。**この左カラムが今回の悩みをそのまま解決する。**

| unshift.jp の左カラム | 今回への置き換え |
|---|---|
| ← 戻る | 一覧に戻る（同じ） |
| タイトル（塗りラベル）＋日本語サブタイトル | プロダクト名＋1行説明（同じ） |
| カテゴリ：Webサイト | 区分：サービス開発 / Web制作 |
| 役割：フロントエンド | 役割：企画・開発・運用 など |
| タグ：GLSL / three.js / HTML/CSS … | 使用技術：Python / 〇〇（**この形式がそのまま使える**） |
| **「このサイトは既に閉鎖されています。」**（灰色の枠。押せないボタンの位置） | **「このサービスの利用にはログインが必要です」** |
| 「サイトにアクセス ⧉」（生きている場合） | 誰でも使える3本はこちら |

**unshift.jp も「リンクは出すが来訪者は中に入れない」という同じ問題を抱えていた**（閉鎖済みサイトが並ぶため）。
その解決が、ボタンの位置に灰色の注意書きを置く形だった。今回の「ログインが必要」も同じ構造なので、
この枠をそのまま借りられる。

## 3. daijima.jp

unshift.jp とはまったく別物。真っ黒な画面に3Dスキャンした本人の頭部が置かれ、
粒子の雲 → ワイヤーフレーム → 実体、と変形し続ける。音つき。1画面完結、スクロールなし。
肩書きは Technical Director / Interaction Designer。

| 要素 | 作り | 今回 |
|---|---|---|
| 背景 | 真っ黒一色。模様なし | ❓ |
| ロゴ | マークなし。氏名をそのまま組んだだけ | 採れる |
| ナビ | 名前の下に ABOUT / BLOG / CONTACT の3語だけ。極小 | 採れる |
| SNS | 右上にアイコン6つ横一列 | ❓ |
| 中央 | 3Dスキャンの頭部（three.js）が常時変形 | 採れない |
| 音 | BGMつき。右下に「Sound by ◯◯」 | 採らない |

採れるのは **「極端な引き算」の作法** だけ。

**daijima.jp は作品を1つも並べていない**（サイト自体が作品）。今回は9本を見せるのが目的なので、
この構成は取れない。

## 4. 構造モックでの検証結果

`docs/unshift-style-mock.html` に、上記の作法のうち **CSS/素のJSで作れるもの** を実際に組んで確認した。
すべて外部ライブラリなしの1ファイルで動く。

| 作法 | 実装 | 結果 |
|---|---|---|
| 四隅固定レイアウト | `position:absolute` ＋ 角ごとのコンテナ | 問題なし。メニュー位置3種の切り替えも成立 |
| 中央1点主義 | 中央にビジュアル、直下にタイトルと区分 | 問題なし |
| 送り操作3系統 | 矢印キー / ホイール / スワイプ | 問題なし。タップ環境では操作ヒントを出し分け |
| オドメーター式ページ送り | 0〜9を縦積みして `translateY` | 問題なし。繰り上がりも自然 |
| カーソル追従 | `pointermove` ＋ 慣性補間 | 問題なし。`@media (hover:none)` で非表示 |
| 設定パネル | 表示モード／メニュー位置／配色。localStorage 保存 | 問題なし |
| ライト／ダーク | CSS変数の再定義のみ | 問題なし。OS追従も動く |
| 幾何パターン背景 | SVGノイズを生成して敷く | 問題なし |
| 合成モード | `mix-blend-mode` | **要注意。** `difference` は白背景で像が飛ぶ。`multiply`（明）/`screen`（暗）に倒した |
| 破れた縁 | 未実装 | 方向性（A/B/C）が未決のため保留 |
| 貼り紙ラベル | 未実装 | 同上 |
| **作品の色を全体に流す** | **未実装** | **★の本丸。ここが自分の色を入れる最初の場所** |

**判明した注意点が1つ。** `mix-blend-mode: difference` は参考サイトの見た目に近いが、
白基調だと暗い要素が反転して消える。明暗どちらの基調にするかを先に決めないと、この選択が決まらない。

## 5. 静的HTMLでどこまで寄せられるか

| やりたいこと | 手段 | 参考サイトとの差 |
|---|---|---|
| プロダクトごとに色が変わる | データに色を1つ持たせCSS変数へ | **差はない** |
| ラベル・カーソルも連動 | 同じCSS変数を参照 | 差はない |
| 四隅にUIを固定 | CSSのみ | 差はない |
| 破れた縁 | マスク画像1枚 | 差はない（止まった状態なら） |
| 貼り紙ラベル | `text-shadow` 二重掛け | 差はない |
| 数字がめくれるページ送り | 0〜9縦積み＋`translateY` | 差はない |
| 設定パネル | CSSクラス付け外し＋localStorage | 差はない |
| 背景に幾何学パターン | SVGパターンを敷く | ほぼない |
| パターンがゆっくり動く | CSSアニメーションで平行移動・回転 | 単調な繰り返しになる |
| 画像が砕けて切り替わる | — | **再現不可** |

## 6. 採否

| 要素 | 判断 | 理由 |
|---|---|---|
| 配色（ほぼ白＋作品だけが色を持つ） | **採る** | 画面写真が主役の今回と相性が良い |
| 四隅にUIを固定するレイアウト | **採る** | 中央を写真に明け渡せる。CSSのみ |
| ナビは3つだけ・広い字間 | **採る** | 今回も Works / About / Contact の3つ |
| ライト／ダークモード | **採る** | 確定済みのスマホ対応と同じ仕組みで入る |
| うっすらした幾何パターン背景 | **採る** | 白一色より締まる。画像1枚 |
| 詳細ページの左カラム構成 | **採る** | 「ログインが必要」の見せ方がそのまま借りられる |
| 画像の破れた縁 | ❓ 要確認 | 実現可。方向性（8節）次第 |
| 貼り紙風タイトルラベル | ❓ 要確認 | 実現可。方向性（8節）次第 |
| カーソルの明暗反転 | ❓ 要確認 | 一覧データに「明るい/暗い」を1項目持たせるだけ |
| スクロール連動の表示 | ❓ 要確認 | 実現可。入れるほどスマホで重くなる |
| 数字がめくれるページ送り | ❓ 要確認 | 一覧形式なら出番がないかもしれない |
| 来訪者が選べる設定パネル | ❓ 要確認 | 表示モード3種＝実質サイト3つ。ライト/ダークのみに絞ることを推奨 |
| 全画面1件ずつのビューア | 採らない | ログイン必須の業務画面に不向き |
| 画像が砕ける切り替え演出 | 採らない | WebGL。静的HTML方針と画像軽量化方針の両方に反する |

### 構成は借りない

unshift.jp の作品は「水曜日のカンパネラ 公式サイト」のような、画像1枚で成立する制作物。
全画面1件ずつのビューアは、**作品が視覚的に強いからこそ機能する。**

今回のサービス開発6本はログインが必要な業務アプリで、画面の中身は入力欄と一覧表。
全画面に引き伸ばしても絵として持たず、クリックしてもログイン画面に着く。

**構成は借りず、見た目の作法だけを借りる。**

### 要点

借りるのは「静けさ」。具体的には次の3つ。

1. 余白を広く取る
2. 色を作品にしか使わない
3. 操作UIを画面の端に追いやる

## 7. デザイントークン（たたき台）

構造モックで実際に使っている値。ここを起点に自分の色へ寄せていく。
すべて `:root` にまとめてあり、ダークは同じキーの再定義だけで切り替わる。

### 配色

| トークン | ライト | ダーク | 用途 |
|---|---|---|---|
| `--c-bg` | `#ffffff` | `#0a0a0a` | 地 |
| `--c-ink` | `#0a0a0a` | `#f2f2f2` | 本文・見出し |
| `--c-ink-2` | 55%不透明 | 55%不透明 | 補助テキスト |
| `--c-ink-3` | 28%不透明 | 28%不透明 | ラベル・注記 |
| `--c-line` | 14%不透明 | 16%不透明 | 罫線・枠 |
| `--c-panel` | `#ffffff` | `#131313` | パネル・ボタン地 |
| `--c-veil` | 白86% | 黒86% | オーバーレイ |
| **`--work-color`** | **未設定** | **未設定** | **★ 作品ごとの色。ここが本丸** |

いまは白黒のみ。`--work-color` を足して 2.2 の仕組みを入れるのが次の一手。

### 書体

| トークン | 内容 |
|---|---|
| `--font-en` | Helvetica Neue / Arial → Hiragino Sans / Noto Sans JP |
| `--font-jp` | Hiragino Sans / Noto Sans JP / Yu Gothic UI / Meiryo |
| `--font-mono` | SFMono / Menlo / Consolas（ラベル・数字・注記に使用） |

Webフォントは読み込んでいない。表示速度の要件（4章）を優先している。
ラベル類を等幅にするだけで、参考サイトの「広い字間」の印象がかなり出る。

### 余白・寸法

| トークン | 値 | 用途 |
|---|---|---|
| `--u` | `8px` | 余白の基本単位 |
| `--edge` | `24px`（スマホ `16px`） | 画面端の余白 |
| `--btn` | `56px`（スマホ `48px`） | 角ボタンの一辺 |
| `--dur` / `--ease` | `.6s` / `cubic-bezier(.22,.61,.36,1)` | 動きの基準 |

## 8. 未決の論点

### 8.1 方向性：破れた縁と貼り紙ラベルを採るか

手作りっぽさ・勢いのある見た目。unshift.jp は色鮮やかな広告・音楽系の制作物が並ぶので
この荒さが似合う。

今回のサイトは採用担当や取引先に「業務システムを任せられる人」として見られる場でもある。
破れた縁は目を引くが、**堅さや信頼感とは逆方向に働く。** 好みではなく、
**誰に何と思われたいか**の問題。

| 選択肢 | 内容 |
|---|---|
| A | 採用する（印象重視） |
| B | 直角のまま静かに（信頼感重視） |
| C | 受託制作の2本だけ採用 |

### 8.2 ★ 作品ごとに色を変える仕組みの採否

**最優先。強く推奨。** 後から足すのが一番高くつく（一覧データの形が変わるため）。
採るなら、棚卸しした8本それぞれに色を1つ決める作業が要る。

### 8.3 全体の明るさの初期値

白基調（unshift 寄り）か、黒基調（daijima 寄り）か。
4節のとおり、これが決まらないと `mix-blend-mode` の選択も決まらない。

### 8.4 その他

- 背景パターンをどこまで動かすか（静止 / ゆっくり / 色も変える）
- カーソル追従・スクロール連動・数字めくりの各要否 → **モックで動くので見て決められる**
- 設定パネルをライト/ダークのみに絞るか
- 未確認2サイト（junkata.com / p5aholic）を見る必要があるか
